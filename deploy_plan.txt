================================================================================
② 信息收集小教程（一步一步获取上面 18 项）
================================================================================

②.1 ${SSH_USER} / ${ROOT_PASSWORD} —— 在腾讯云控制台获取
   1) 登录 https://console.cloud.tencent.com/cvm
   2) 找到公网 IP=43.153.210.122 的实例 → 「更多」→「重置密码」
      （如果你已经设置过 SSH 密钥，可跳过；否则在这里设置一个临时密码）
   3) 镜像若是 Ubuntu 22.04，则默认登录用户 = `ubuntu`
   4) SSH 端口默认是 22；可在「安全组」中确认未改
   5) 第一次登录：
        ssh ubuntu@43.153.210.122
        # 输入临时密码

②.2 ${SSH_KEY_PATH} —— 生成本机 SSH 密钥（推荐用密钥替换密码）
   本机执行：
        test -f ~/.ssh/id_ed25519 || ssh-keygen -t ed25519 -C "trax-deploy"
        cat ~/.ssh/id_ed25519.pub                       # 复制这一行
   然后远端：
        ssh ubuntu@43.153.210.122
        mkdir -p ~/.ssh && chmod 700 ~/.ssh
        echo '<刚才复制的pub内容>' >> ~/.ssh/authorized_keys
        chmod 600 ~/.ssh/authorized_keys
   验证：本机重新 `ssh ubuntu@43.153.210.122` 不再要密码即成功。
   填入：${SSH_KEY_PATH}=~/.ssh/id_ed25519

②.3 ${LOCAL_OUT_IP} —— 你的公网出口 IP（用于安全组 SSH 白名单）
   本机：
        curl -s https://ifconfig.me ; echo
        # 或浏览器访问 https://ip.sb
   把返回的 IP 填到 ${LOCAL_OUT_IP}。如果你的网络是动态的（家庭宽带常见），
   就先写 0.0.0.0/0 也可，但一定要保留 fail2ban + 密钥登录（见阶段 1）。

②.4 ${JWT_SECRET} —— 随机密钥
   本机或服务器：
        openssl rand -base64 48
   把输出整行（一串字母数字+/=）复制到 ${JWT_SECRET}。

②.5 ${MYSQL_ROOT_PWD} / ${MYSQL_PWD} —— 自己定，强密码生成器
   建议：
        openssl rand -base64 24 | tr -d '=+/'
   生成两条独立的随机串，分别给 root 和业务账号。务必保存到密码管理器。

②.6 ${DOMAIN} —— 域名解析（强烈建议有；纯 IP 也能跑但无 HTTPS）
   1) 在域名注册商（腾讯云 DNSPod、阿里云、Cloudflare 任一）后台
      新增一条 A 记录：
            主机记录: api          （或你想要的子域）
            记录类型: A
            记录值:   43.153.210.122
            TTL:      默认 600
   2) 几分钟后本机验证：
            nslookup api.你的域名.com
      返回 43.153.210.122 即生效。
   3) 把完整 FQDN 填到 ${DOMAIN}，例如 api.trax.example.com

   说明：没域名也可以用 IP 访问 + 自签证书，但 iOS App 默认禁止
        非 HTTPS 公网请求，强烈不推荐。

②.7 ${ADMIN_EMAIL} —— Let's Encrypt 注册邮箱
   一个常用、能收到通知的邮箱即可（证书将于到期前 30 天发提醒）。

②.8 ${GMAPS_KEY} / ${GMAPS_KEY_MOBILE} —— Google Maps API Key
   两枚不同 Key，限制方式不同：

   服务器端 Key（${GMAPS_KEY}，给后端 Static Maps / Geocoding 用）：
   1) 浏览器打开 https://console.cloud.google.com/
   2) 选 / 新建项目 → 「API 和服务」→「库」
        启用：Maps Static API、Geocoding API、Directions API（按需）
   3) 「凭据」→「创建凭据」→「API 密钥」→ 命名 trax-server
   4) 编辑该 Key →「应用限制」选「IP 地址」→ 添加 43.153.210.122
                  →「API 限制」勾选上面启用的几项
   5) 保存 → 把 Key 字符串填到 ${GMAPS_KEY}

   移动端 Key（${GMAPS_KEY_MOBILE}，给 google_maps_flutter 用）：
   1) 同项目 → 启用：Maps SDK for Android、Maps SDK for iOS
   2) 再「创建凭据」→ API 密钥 → 命名 trax-mobile
   3) 「应用限制」选「Android 应用」加 package name + SHA-1，
      再加一条「iOS 应用」加 bundle id
   4) 保存 → 填到 ${GMAPS_KEY_MOBILE}

   计费：Google Maps 需要绑定结算账号（每月有免费额度，开发期足够）。

②.9 ${APP_USER}/${APP_DIR}/${IMG_DIR}/${MYSQL_DB}/${MYSQL_USER}
   这些直接采用本文件给的默认值即可，无需另外查询。

完成上面 ②.1～②.8 后，整张 Checklist 应当 100% 填齐。继续 ▶ 阶段 0。

        sudo ufw default deny incoming
        sudo ufw default allow outgoing
        sudo ufw allow ${SSH_PORT}/tcp
        sudo ufw allow 80/tcp
        sudo ufw allow 443/tcp
        sudo ufw enable
        sudo ufw status verbose
1.6  SSH 加固（确认密钥登录已成功后再做）：
        sudo sed -i 's/^#\?PasswordAuthentication.*/PasswordAuthentication no/' /etc/ssh/sshd_config
        sudo sed -i 's/^#\?PermitRootLogin.*/PermitRootLogin no/' /etc/ssh/sshd_config
        sudo systemctl restart ssh
1.7  防暴力破解：
        sudo apt -y install fail2ban
        sudo systemctl enable --now fail2ban

阶段 3 · 初始化 MySQL（关键）
================================================================================
3.1  设置 root 密码 & 安全初始化：
        sudo mysql <<SQL
        ALTER USER 'root'@'localhost' IDENTIFIED WITH caching_sha2_password
            BY '${MYSQL_ROOT_PWD}';
        FLUSH PRIVILEGES;
        SQL
        sudo mysql_secure_installation
        # 提示按以下回答：
        #   VALIDATE PASSWORD COMPONENT? n
        #   Change root password? n（已设置）
        #   Remove anonymous users? Y
        #   Disallow root login remotely? Y
        #   Remove test database? Y
        #   Reload privilege tables? Y

3.2  创建业务数据库 + 账号（注意 utf8mb4，支持 emoji 与中文）：
        mysql -uroot -p"${MYSQL_ROOT_PWD}" <<SQL
        CREATE DATABASE \`${MYSQL_DB}\`
            CHARACTER SET utf8mb4 COLLATE utf8mb4_0900_ai_ci;
        CREATE USER '${MYSQL_USER}'@'127.0.0.1' IDENTIFIED BY '${MYSQL_PWD}';
        CREATE USER '${MYSQL_USER}'@'localhost' IDENTIFIED BY '${MYSQL_PWD}';
        GRANT ALL PRIVILEGES ON \`${MYSQL_DB}\`.* TO '${MYSQL_USER}'@'127.0.0.1';
        GRANT ALL PRIVILEGES ON \`${MYSQL_DB}\`.* TO '${MYSQL_USER}'@'localhost';
        FLUSH PRIVILEGES;
        SQL

3.3  锁定 MySQL 仅监听本机（不对外暴露 3306）：
        sudo sed -i 's/^bind-address.*/bind-address = 127.0.0.1/' \
             /etc/mysql/mysql.conf.d/mysqld.cnf
        sudo systemctl restart mysql
        ss -lntp | grep 3306        # 应仅看到 127.0.0.1:3306

3.4  常用调优（可选，按机型酌情）：
        sudo tee -a /etc/mysql/mysql.conf.d/mysqld.cnf >/dev/null <<EOF

        [mysqld]
        max_connections        = 200
        innodb_buffer_pool_size= 512M
        innodb_flush_log_at_trx_commit = 2
        slow_query_log         = 1
        slow_query_log_file    = /var/log/mysql/slow.log
        long_query_time        = 1
        EOF
        sudo systemctl restart mysql

3.5  自动备份脚本占位（详见阶段 9，使用 mysqldump）。

验收：
        mysql -u${MYSQL_USER} -p"${MYSQL_PWD}" -h 127.0.0.1 \
              -e "SHOW DATABASES;" | grep ${MYSQL_DB}
   能看到 trax 库即成功；外网 telnet 43.153.210.122 3306 应不通。

阶段 5 · 后端代码改造（H2 → MySQL）
================================================================================
本仓库现有 backend/ 当前用 H2，需做 4 处小改造（一次性）：

5.1  backend/pom.xml —— 把 h2 依赖替换为 mysql 驱动：
        删除：
            <dependency>
                <groupId>com.h2database</groupId>
                <artifactId>h2</artifactId>
                <scope>runtime</scope>
            </dependency>
        新增：
            <dependency>
                <groupId>com.mysql</groupId>
                <artifactId>mysql-connector-j</artifactId>
                <scope>runtime</scope>
            </dependency>

5.2  backend/src/main/resources/application.yml（开发用，可保留 H2）
     不动；生产用单独 application-prod.yml（见阶段 6）。

5.3  实体扫描 / 类型差异检查：
        • @Lob 字段在 MySQL 默认 LONGTEXT，OK；
        • Trail/RidePoint/Telemetry 中 double 列在 MySQL 是 DOUBLE，OK；
        • Boolean → TINYINT(1)，OK；
        • 唯一约束（UserCheckpoint user_id+trail_id+sequence_index）需 MySQL
          能创建索引，OK。
        如果 ddl-auto=update 启动失败（多见于列长度不够），改为
        spring.jpa.hibernate.ddl-auto=create 跑一次再换回 update（仅首次）。

5.4  本地先跑通：
        本机：在 application.yml 临时加一份 spring.profiles=local-mysql 的
        块，连接 docker 起的 mysql:8 测一遍；通过后再发布。

阶段 6 · 生产配置 application-prod.yml
================================================================================
6.1  写到 ${APP_DIR}/current/application-prod.yml：

        spring:
          datasource:
            url: jdbc:mysql://127.0.0.1:3306/${MYSQL_DB}?useSSL=false&characterEncoding=utf8mb4&serverTimezone=Asia/Shanghai&allowPublicKeyRetrieval=true&rewriteBatchedStatements=true
            driver-class-name: com.mysql.cj.jdbc.Driver
            username: ${MYSQL_USER}
            password: ${MYSQL_PWD}
            hikari:
              maximum-pool-size: 20
              minimum-idle: 5
              connection-timeout: 30000
          jpa:
            hibernate:
              ddl-auto: update
            show-sql: false
            properties:
              hibernate.dialect: org.hibernate.dialect.MySQL8Dialect
              hibernate.jdbc.batch_size: 50
              hibernate.order_inserts: true
              hibernate.order_updates: true
          web:
            resources:
              static-locations: classpath:/static/,file:${IMG_DIR}/
        server:
          port: 8080
          address: 127.0.0.1                 # 仅本机监听，由 Nginx 反代
          forward-headers-strategy: framework
          tomcat:
            max-swallow-size: 20MB
            max-http-form-post-size: 20MB
        spring.servlet.multipart:
          max-file-size: 20MB
          max-request-size: 20MB
        jwt:
          secret: ${JWT_SECRET}
          expiration: 86400000
        google:
          maps:
            api-key: ${GMAPS_KEY}
        logging:
          file:
            name: /var/log/trax/trax-backend.log
          level:
            root: INFO
            com.trax: INFO

     注意：上文中的 ${MYSQL_DB}/${MYSQL_USER}/${MYSQL_PWD}/${JWT_SECRET}/
     ${GMAPS_KEY} 不是 Spring 占位符，是让你替换成实际值的占位符。最终 yml
     里要么写死，要么改成 ${ENV_VAR} 由 systemd 注入（推荐，见阶段 7）。

6.2  推荐做法：把敏感字段改成 ${ENV_VAR}，由 systemd 的 Environment 注入：
        spring.datasource.password: ${MYSQL_PWD}
        jwt.secret:                 ${JWT_SECRET}
        google.maps.api-key:        ${GMAPS_KEY}
     这样 yml 可入版本库，密钥仍只在服务器上。

验收：cat ${APP_DIR}/current/application-prod.yml；字段无误。

阶段 8 · systemd 服务化
================================================================================
8.1  /etc/systemd/system/trax-backend.service：
        [Unit]
        Description=TRAX Backend (Spring Boot, MySQL)
        After=network-online.target mysql.service
        Wants=network-online.target
        Requires=mysql.service

        [Service]
        User=${APP_USER}
        Group=${APP_USER}
        WorkingDirectory=${APP_DIR}/current
        Environment="JAVA_OPTS=-Xms512m -Xmx1024m -XX:+UseG1GC -Dfile.encoding=UTF-8"
        Environment="MYSQL_PWD=__此处填实际值__"
        Environment="JWT_SECRET=__此处填实际值__"
        Environment="GMAPS_KEY=__此处填实际值__"
        ExecStart=/usr/bin/java $JAVA_OPTS \
            -Dspring.profiles.active=prod \
            -Dspring.config.additional-location=file:${APP_DIR}/current/application-prod.yml \
            -jar ${APP_DIR}/current/trax-backend.jar
        SuccessExitStatus=143
        Restart=always

阶段 11 · 数据备份策略（MySQL）
================================================================================
11.1 /usr/local/bin/trax-backup.sh：
        #!/usr/bin/env bash
        set -euo pipefail
        TS=$(date +%Y%m%d-%H%M%S)
        OUT=/var/backups/trax
        mkdir -p $OUT
        # 用 root 跑 mysqldump（密码从受保护的 my.cnf 读取，避免命令行泄密）
        mysqldump --defaults-file=/root/.trax-backup.cnf \
                  --single-transaction --quick --routines --triggers \
                  --databases ${MYSQL_DB} \
                | gzip -9 > $OUT/trax-db-$TS.sql.gz
        # 静态图片一并打包
        tar czf $OUT/trax-img-$TS.tgz -C /var/lib/trax images
        # 14 天前的清掉
        find $OUT -name 'trax-*' -mtime +14 -delete

11.2 受保护的密码文件（避免明文出现在 ps 输出）：
        sudo tee /root/.trax-backup.cnf >/dev/null <<EOF
        [mysqldump]
        user=root
        password=${MYSQL_ROOT_PWD}
        host=127.0.0.1
        EOF
        sudo chmod 600 /root/.trax-backup.cnf

11.3 加可执行 + cron 每天 03:00：
        sudo chmod +x /usr/local/bin/trax-backup.sh
        echo "0 3 * * * root /usr/local/bin/trax-backup.sh" | \
             sudo tee /etc/cron.d/trax-backup

11.4 异地：把 /var/backups/trax 定期 rsync 到本机或腾讯云 COS（推荐）。

11.5 恢复演练（极重要，至少季度一次）：
        gunzip -c trax-db-XXXX.sql.gz | mysql -uroot -p"${MYSQL_ROOT_PWD}"
        tar xzf trax-img-XXXX.tgz -C /var/lib/trax/

验收：手动跑一次脚本，/var/backups/trax/ 同时有 .sql.gz 和 .tgz。

阶段 17 · 常见问题排查
================================================================================
• 502 Bad Gateway
     systemctl status trax-backend
     /var/log/trax/trax-backend.log
     journalctl -u trax-backend -n 200

• 后端启动报 "Communications link failure / Public Key Retrieval"
     application-prod.yml 的 url 缺少 allowPublicKeyRetrieval=true 或 useSSL=false

• ddl-auto=update 启动失败（列长度/字符集冲突）
     先 mysqldump 备份 → 把 ddl-auto 改为 create-drop 跑一次（仅开发环境）→
     校对失败列后回到 update。生产慎用 create-drop。

• 中文 / Emoji 乱码
     确认建库 utf8mb4_0900_ai_ci；jdbc url 含 characterEncoding=utf8mb4；
     systemd Environment 加 -Dfile.encoding=UTF-8（已加）。

• MySQL 连接数打满（Too many connections）
     调高 max_connections，并把 Hikari maximum-pool-size 与之匹配。

• 头像 marker 不更新
     抓包确认 URL 含 ?v=<epoch>；检查 AvatarUrls.versioned 是否覆盖所有 DTO。

• Static Maps 在生产打不开
     服务器需可访问 maps.googleapis.com；如腾讯云境内出网受限，改用国内地图
     或在第三方海外节点做代理转发。

• 证书续期失败
     certbot renew --dry-run；确保 80 端口未被其它进程占用，且 ${DOMAIN}
     A 记录仍指向 43.153.210.122。

• 时间不同步导致 JWT 过期错乱
     systemctl status chrony；timedatectl status

• 磁盘爆满
     du -sh /var/log/* /var/lib/mysql /var/backups/* | sort -h
     检查 logrotate；删除过期备份；MySQL binlog 若开启需 expire_logs_days。
