================================================================================
TRAX — Full From-Scratch Build Prompt Pack
================================================================================
Audience: an AI coding agent that will recreate the entire TRAX product
(Spring Boot backend + Flutter mobile app) from an empty repository.

How to use this file:
  • Execute modules M0 → M28 in order.
  • Each module is self-contained: GOAL, INPUTS, DELIVERABLES, ACCEPTANCE.
  • Final form only — no iteration history, no patch language. Re-running
    the modules from scratch must produce a product equivalent to the
    current state of this repository.
  • Code style: Java 17 / Spring Boot 3.4 for backend; Dart 3 / Flutter 3
    with GetX for the app. No Lombok. Keep DTOs as plain POJOs.

Self-validation gates run after each major module:
  ▸ backend: `cd backend && mvn -q -DskipTests compile`
  ▸ frontend: `cd trax_app && flutter analyze`
  ▸ end-to-end smoke: backend boots on :8080, app launches on iOS sim,
    user can register → log in → create bike → record trail → host race.

M3 · Backend Domain Model (JPA Entities)
================================================================================
GOAL: complete persistence model. All entities under com.trax.model with
plain getters/setters and @PrePersist/@PreUpdate where noted.

Identity & Garage
  • User (table users) — id, email (unique), password (BCrypt), name,
    avatarUrl, rewardPoints, OneToMany bicycles, createdAt, updatedAt.
    @PrePersist sets both timestamps; @PreUpdate refreshes updatedAt.
    (updatedAt is the source of the avatar cache-buster — see M7.)
  • Bicycle — name, motor, controller, battery, other, imageUrl,
    traxSerialNumber, motorCertified/controllerCertified/batteryCertified,
    ManyToOne owner→User (NOT NULL), ManyToOne model→BikeModel (nullable),
    ManyToOne module→TraxModule (nullable). Created/updatedAt with hooks.
  • HistoryBicycle — flat snapshot of Bicycle for archival on delete.
    Static factory fromBicycle(b). archivedAt set on @PrePersist.
  • BikeBrand — id, name (unique), imageUrl, OneToMany models.
  • BikeModel — brand, modelName, imageUrl, motorType, motorPeakPowerW,
    motorTorqueNm, controller, batteryType, batteryVoltage,
    batteryCapacityWh.
  • TraxModule — serialNo (unique), name, bound (boolean default false),
    ManyToOne model→BikeModel (nullable, EAGER).

Telemetry
  • ModuleTelemetry — module, lat, lng, speed, batteryPercent,
    signalStrength, timestamp.
  • ControllerTelemetry — 26-channel VESC payload (FET temp, motor temp,
    avg motor/input current, id/iq, duty cycle, RPM, input voltage,
    Ah/Wh cumulative, encoder sin/cos, throttle/regen ADC, fault code,
    digital input state, controller id, NTC MOS A/B/C, Vd/Vq,
    odometerM, speedKmh, rsMode, assistLevel). 1:1 to a RidePoint by id,
    indexed by ride_id and timestamp.

Trails
  • Trail — name, location, difficulty (EASY/MEDIUM/HARD/EXTREME),
    description, imageUrl, distance, elevation, type (`free_ride` | `lap`),
    creatorId, start/endLatitude, start/endLongitude, createdAt,
    deleted=false, isPublic=true.
  • TrailPoint — trail FK, latitude, longitude, altitude, sequenceIndex,
    timestamp.
  • UserCheckpoint — per-user trail CPs (max 4); unique
    (user_id, trail_id, sequence_index); lat/lng; createdAt.

Rides
  • RideRecord — user, trail, bicycle, startTime, endTime, distance,
    avgSpeed, maxSpeed, elevation, weather, status
    (active|paused|completed), mode (with_module|without_module),
    totalPausedSeconds, lastPausedAt, targetLaps, completedLaps,
    source (free_ride|lap_timer|race), hiddenByOwner.
  • RidePoint — ride, lat, lng, speed, altitude, timestamp.
  • RideLap — rideId, lapNumber (unique with rideId), startTime, endTime,
    durationSeconds, distanceKm, overlapPercent.
  • RideLapCheckpoint — lapId, sequenceIndex (unique with lapId),
    passTime, lat, lng.
  • HistoryRideRecord / HistoryRidePoint — archival mirrors.

Races
  • Race — host (User), trail, name, scheduledTime, maxParticipants,
    targetLaps, isPublic, notes, joinCode (6 chars, unique), status
    (waiting|preparing|in_progress|completed|canceled), gameType
    (`RACE`|`LAPS`, default RACE), startedAt, endedAt, createdAt.
  • RaceParticipant — race, user (unique together), role
    (host|rider|observer), ride (nullable), bicycle (nullable), joinedAt,
    status (joined|ready|racing|finished|dnf), finishRank, bestLapSeconds,
    latitude, longitude.

Misc
  • Performance — best-time/best-speed snapshot per user/trail/ride.
  • Product — id, name, description, price, imageUrl, category
    (new|secondhand), type (conversion_kit|accessory).

ACCEPTANCE: schema auto-creates on first boot under traxdb.mv.db.

M7 · Backend AvatarUrls Wiring
================================================================================
Every DTO that emits an avatar URL must route through
`AvatarUrls.versioned(...)`. Required emission sites:
  1. AuthService.buildLoginData → UserDto.
  2. RaceParticipantDto.fromEntity (host, rider, observer rows).
  3. RaceDto.fromEntity (hostAvatarUrl).
  4. RaceLiveDto.RiderLiveInfo (per-rider avatar in live polling payload).
  5. (Trail creator avatars when surfaced through TrailDto.creator.)

Rationale: Flutter `NetworkImage`/marker bitmap caches key by URL.
Bumping `?v=<updatedAt>` deterministically invalidates them on profile edit.

M8 · Backend Services
================================================================================
com.trax.service:

AuthService
  • register(RegisterRequest) → save User with BCrypt, emit LoginData.
  • loginByPwd(LoginByPwdRequest) → authenticate by email or username,
    issue JWT, build LoginData(accessToken, "Bearer", UserDto).
  • resetPassword, checkEmailAvailable.
  • buildLoginData(User) → wraps avatar via AvatarUrls.versioned.

UserService
  • profile, updateProfile (uploads avatar to /backend/images/avatars/<id>.png
    via static-resource path and stamps user.avatarUrl).

BikeBrandService / BikeModelService / TraxModuleService — CRUD reads.

BicycleService — CRUD against current authenticated user; on delete, copy
into HistoryBicycle then remove.

TrailService
  • createTrail(payload) → optimize incoming points via TrailOptimizer,
    compute distance/elevation, persist Trail + TrailPoints; auto-set
    start/end LatLng from first/last points.
  • listPublicTrails, listMyTrails, get, softDelete.
  • getPoints(trailId) (downsampled if huge), togglePublic.
  • UserCheckpointService — list/add/delete; max 4 per (user, trail).

RideService — the algorithmic core.
  • startRide(bikeId, trailId, mode, source, targetLaps?).
  • appendPoints(rideId, batch) → persist RidePoints, recompute distance
    and avg/max speed running totals, perform live LAP DETECTION:

    Lap detection algorithm (CLIENT MUST MIRROR THIS — see M19):
      • startPoint = first sample of the ride.
      • headingUnit = unit vector (north,east) toward the first sample
        ≥ 5.0 m from startPoint.
      • finishLine = perpendicular through startPoint with half-width
        15 m on each side (`lapFinishLineHalfWidthKm = 0.015`).
      • For each adjacent pair (prev, curr) of samples, compute
        segmentIntersectionParam((prev,curr), (A,B)). On intersection:
          – Velocity vector v = curr - prev.
          – Forward filter: dot(v, headingUnit) > 0 (only count when
            crossing in the same direction as the original lap heading).
          – Hysteresis: maxAwayKm since last lap close ≥ 0.15 km AND
            elapsed seconds since last lap close ≥ 15.
        If all three pass: linearly interpolate the exact crossing
        lat/lng/altitude/timestamp using the segment parameter t and
        emit a RideLap. Reset maxAwayKm + lap-start time.
      • Whenever rider passes a UserCheckpoint within 25 m, append a
        RideLapCheckpoint to the in-progress lap.
  • pauseRide / resumeRide (track totalPausedSeconds).
  • stopRide → status=completed, finalize stats.
  • deleteOwnRide → set hiddenByOwner=true (other users still see in races).
  • listMyRides, getRideStats, getRidePoints, getRideLaps.

RaceService
  • createRace(payload) → host inserted as RaceParticipant role=host;
    generates 6-char joinCode (uppercase alphanum).
  • listPublic, listPublicForObserver, listMyEvents (paged), get(id).
  • joinRace(id, bicycleId?), joinByCode(code, role, bicycleId?),
    observeRace, quitRace, setBike, updateType (public/private toggle).
  • startRaceEvent → status=preparing (riders ready up & report GPS).
  • readyForRace → participant.status=ready.
  • goRace → status=in_progress, startedAt=now, auto-create a RideRecord
    (source=race) for every rider participant.
  • stopRaceEvent → status=completed, endedAt=now; for each rider, finalize
    its underlying RideRecord; assign finishRank by laps completed
    (RACE mode) or bestLapSeconds (LAPS mode); riders with
    completedLaps<targetLaps get status=dnf.
  • cancelRaceEvent.
  • reportLocation(raceId, lat, lng) → updates participant lat/lng AND, if
    in_progress, appends a RidePoint to the rider's RideRecord (which
    triggers lap detection).
  • getRaceLive(id) → assembles RaceLiveDto with each rider's polyline so
    far + completed laps + lastCheckpointIndex.

ImageDownloadService — downloads bike images by brand/model name into
/backend/images/bikes/<BRAND>/<model>.png using jsoup-scraped Bing image
search; falls back to createPlaceholderImage() (gray PNG with text).

M18 · Trail Record (4 modes)
================================================================================
lib/screens/trails/trail_record_page.dart (902) — single page with four
recording modes selectable from the idle controls bar. Shared structure:
  • Status FSM: idle | recording | paused | stopped.
  • GoogleMap with map-type toggle (normal/satellite/hybrid/terrain).
  • Bottom panel showing current distance, elapsed, sample count,
    plus mode-specific controls.
  • Lat,Lng input bar at top for jump-to-coord.

Modes:
  1. Real GPS — Geolocator.getPositionStream(LocationSettings(accuracy:
     LocationAccuracy.bestForNavigation, distanceFilter: 5)). Append each
     fix into `_route` (List<LatLng>) and `_points` (List<_RecordedPoint>
     {lat,lng,altitude,timestamp}). Live polyline updates.
  2. Pick Location — crosshair pinned to map centre; "Add point" button
     reads `_mapController.getLatLng(centerScreenCoord)` and appends.
  3. Simulate Lap (Draw) — disables map gestures, overlays a transparent
     GestureDetector with onPanStart/Update/End. Each pointer sample is
     converted via `_mapController.getLatLng(ScreenCoordinate)` chained on
     a `Future _drawChain` so calls serialize. Downsample by 6 px screen
     distance. Polyline updates in real time. Toolbar: Clear / Cancel /
     Finish; Finish wraps the points as `_RecordedPoint`s and pushes
     TrailSavePage.
  4. Start Lap Recording — starts a real-GPS recording but auto-stops
     when the rider crosses the lap finish line, then trims the route to
     a clean loop and pushes TrailSavePage. **Algorithm must match the
     backend RideService lap detector exactly:**
       • startPoint = first sample.
       • headingUnit = unit vector to the first sample ≥ 5.0 m away from
         start (`headingRefMinMeters = 5.0`).
       • Build perpendicular finish-line endpoints A,B at ±15 m from
         start (`lapFinishLineHalfWidthKm = 0.015`).
       • For each adjacent (prev, curr) call `segmentIntersectionParam`
         between (prev,curr) and (A,B). On intersection:
           – Forward filter: `dot(curr-prev, headingUnit) > 0`.
           – Hysteresis: `_lapMaxAwayKm ≥ 0.15` AND
             elapsedSec ≥ 15 (`lapMinExcursionKm = 0.15`,
             `lapMinDurationSec = 15`).
       • Linearly interpolate the exact crossing lat/lng/altitude/timestamp
         using parameter t, replace the last `_route`/`_points` entry
         with the interpolated value, then call `_onStop()`.
     UI hint banner cycles through:
       waiting-for-first-sample → waiting-for-heading-lock →
       locked, auto-stop armed.
     A blue "Lap Start / Finish" marker is placed at the start point.

Constants are lowerCamelCase (no SCREAMING_SNAKE). Distance helper
`_haversineKm` is defined exactly once.

M23 · Avatar Cache Strategy (cross-cutting)
================================================================================
Frontend rules — no manual cache-busting needed because backend already
appends `?v=<epoch>` (M7):
  • Render plain network avatars with `NetworkImage(url)` /
    `CircleAvatar(backgroundImage: NetworkImage(...))` — Flutter's
    image cache is keyed by full URL.
  • For map marker bitmaps (race_tracking_page, race_replay_page),
    maintain a per-user URL fingerprint (`_avatarUrlByUid` /
    `_markerAvatarUrls`); on change → evict bytes + bitmap and rebuild.
  • Do **not** pass any other cache key to `NetworkImage`.

M24 · Static Maps & Trail Thumbnails
================================================================================
StaticMapUrl.forRoute encodes points into a Google polyline, requesting
size=240x240 scale=2 with the route stroked in AppColors.primary.

`loadTrailThumbnail(trailId, points)`:
  1. Returns from process-lifetime cache if present.
  2. Downsamples to ≤120 points (uniform stride).
  3. Builds the URL via StaticMapUrl.
  4. Fetches via the **debug-proxied** Dio adapter. The same
     `IOHttpClientAdapter` block (PROXY 127.0.0.1:7897 +
     badCertificateCallback) MUST be present in trail_thumbnail.dart,
     trail_detail_page.dart, trail_save_page.dart, trail_record_page.dart
     and any other file that fetches Google APIs in dev. Without it the
     emulator/simulator will hang on Google requests.

  pgrep -f flutter_tools.snapshot | xargs -I{} kill -USR2 {}

rebuild.sh — optional: `mvn -q -DskipTests package && cd trax_app &&

  1. backend:  `cd backend && mvn spring-boot:run`
  2. sims:     boot iPhone 17 / 17 Pro / Air, run
               `cd trax_app && flutter run -d <sim_id>` for each.
  3. iterate:  edit code → `bash hot_restart_all.sh` → verify on all sims.
